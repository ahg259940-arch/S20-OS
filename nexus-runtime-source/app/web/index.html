ASSISTENTE DE HOSPEDAGEM

Escolha onde o mundo ficará

Mesmo aparelho/LAN: sem custo de hospedagem, mas o servidor Java/Bedrock precisa estar instalado e o aparelho ligado; conexões externas exigem configuração de roteador.

Servidor próprio: controle maior, exige PC/VPS ativo, memória, manutenção e firewall.

Hospedagem gerenciada: mais simples e com disponibilidade; pode ter custo mensal, limites e painel externo. Confirme o suporte à edição e versão antes de contratar.

Para um mundo privado, ative whitelist (Java) ou allow-list (Bedrock), use conta proprietária e adicione somente amigos autorizados. Configure RCON com senha forte e restrinja-o à rede confiável se for habilitar automação.

  1. Instale uma versão oficial Java ou Bedrock Dedicated Server compatível.
  2. Aceite o EULA da edição Java quando aplicável e mantenha backups do mundo.
  3. Habilite whitelist/allow-list e adicione proprietário e amigos pelo console do servidor.
  4. Abra apenas TCP Java ou UDP Bedrock no firewall necessário ao jogo.
  5. Para automação, instale plugin/API de comandos autorizado; status de rede sozinho não permite construir.

Acesso e recuperação

A lista é uma referência local. A whitelist/allow-list efetiva precisa ser aplicada no painel/console do servidor.

CONSTRUÇÃO DO DOMÍNIO N.E.X.U.S.

O aplicativo ainda não recebeu um canal de comando (RCON/plugin/API) para inspecionar chunks, permissões ou alterar o mundo. Nenhuma construção foi executada. Para ativá-la é necessário instalar e autorizar uma ponte de comandos compatível com a edição, restringir a credencial e fornecer backups do mundo.

Plano em lotes e execução automática ficam indisponíveis até configurar essa ponte; a consulta de status não é usada como prova de acesso ao mundo.
